# 制作过程后端化（Backend-Hosted Production）方案分析

日期：2026-10-24  
状态：方案草案，尚未实施

## 1. 背景与动因

第一版订阅接入（`easel/subscription.py`）解决了"模型 Key 配置多"的问题：一个 Key 自动配置全部模型通道，对话直连、零网关。但**制作环节仍在用户本机执行**：

| 环节 | 当前执行位置 | 用户侧依赖 |
| --- | --- | --- |
| 对话/文案生成 | 云端（订阅 API） | 无（已解决） |
| 生图/生视频/音乐 | 云端（订阅 API），但由本机脚本发起调用 | Python 环境 |
| 卡片图片渲染 | 本机 Python（Pillow/OpenCV） | Python + 依赖 |
| 视频剪辑/字幕 | 本机 ffmpeg + faster-whisper | ffmpeg + 模型下载 |
| 浏览器操作（登录/发布/取数） | 本机 Playwright + Chromium | ~300MB Chromium |
| 内容归档 | 本机 `outputs/` 目录 | 磁盘 |

非技术用户的完整体验仍需：克隆仓库 → 跑 setup 脚本 → 安装 Python/Node/ffmpeg/Chromium → 启动本地服务。**"一键自动使用"的最后一公里是把制作过程搬到后端**。

## 2. 目标架构

```
┌─ 轻客户端（纯 Web / 桌面壳）────────────┐
│  产品档案 · 活动 · 审核 · 发布记录 · 指标  │
│  素材上传 · 预览 · 回填链接               │
└──────────────┬───────────────────────┘
               │ HTTPS（订阅 Token 鉴权）
┌──────────────▼───────────────────────┐
│  Showly 云端服务                       │
│  ├─ 对话/生成网关（已上线：订阅 API）      │
│  ├─ 制作任务服务（本次方案的核心增量）      │
│  │   ├─ 任务队列（复用 GenerationJob 模型）│
│  │   ├─ 技能执行器容器池（按类型隔离）      │
│  │   └─ 产物对象存储（回传下载/预览 URL）   │
│  └─ 账号/额度/限流（订阅体系）             │
└──────────────────────────────────────┘
```

关键复用：promotion 模块的 GenerationJob（状态机、幂等、重启恢复、输入快照）、ContentRevision（版本与审核绑定）、Publication（人工回填）设计可以直接平移到服务端——它们本来就是围绕"任务化制作"建模的。

## 3. 分阶段路径

### 阶段 A（已完成基础）：模型调用统一走订阅端点
- 对话/文案/生图/视频/音乐的 API 调用参数已由订阅一键配置。
- 本阶段仍由本机发起，但配置成本已归零。

### 阶段 B：纯 API 技能上云（低风险，先行）
- 生图（gpt-image-1）、音乐（Suno）、生视频（sora-2）是"请求-轮询-取产物"型，无本机依赖。
- 做法：云端提供 `POST /api/production/jobs`（接收任务类型+参数+素材引用），服务端调用订阅端点、产物存对象存储、客户端轮询/回调取 URL。
- 客户端改动：把技能脚本的 HTTP 调用换成对 Showly 任务服务的调用；产物从 `outputs/` 本地文件变为 URL 引用（Asset.path 兼容 http 地址）。

### 阶段 C：重计算技能容器化（视频渲染/转写/卡片渲染）
- 卡片图片合成（Pillow）、视频剪辑（ffmpeg）、字幕（whisper）打包为执行器镜像，任务队列调度。
- 执行隔离：每任务独立容器/进程，超时与内存限额；产物只经对象存储回传，容器不落用户数据。
- 冷启动成本用预热池控制；Whisper 模型内置镜像避免每任务下载。

### 阶段 D：发布与登录态托管（最后，风险最高）
- 浏览器自动化（登录/发布/取数）需要托管浏览器农场 + 登录态保险箱。
- 平台风控（小红书检测自动化）使这步风险最高，且第一版产品文档明确"人工发布闭环"——建议维持人工发布，只托管"打开官方入口 + 预填内容 + 回填链接"的辅助。

## 4. 关键决策点

| 决策 | 选项与建议 |
| --- | --- |
| 任务队列 | 起步用数据库表 + 轮询（复用 GenerationJob），规模后再换消息队列 |
| 素材上传 | 预签名 URL 直传对象存储，服务端只存引用；限制单文件大小与总量 |
| 执行隔离 | 容器级（C 阶段必须）；B 阶段纯 API 调用无需隔离，只需限流 |
| 成本与限流 | 按订阅档位限制并发任务数与月产物量；单任务超时熔断 |
| 与本机模式取舍 | 保留现有本机执行作为"高级模式"，云端为默认；两者任务模型同构可互切 |
| 计费口径 | 对话按 token（已有）、制作按任务数（新），产物存储按量 |

## 5. 工作量与风险估算

- 阶段 B：任务服务 + 对象存储 + 客户端改造，约 2-3 人周；风险低（无沙箱问题）。
- 阶段 C：执行器镜像 + 队列调度 + 预热池，约 4-6 人周；风险中（镜像体积、冷启动、长视频任务超时）。
- 阶段 D：托管浏览器 + 登录态安全，约 4+ 人周且持续运营成本高；风险高（平台风控对抗），建议缓行。
- 横切：多租户隔离（每用户独立 outputs 命名空间与数据库行级归属）、配额中间件、审计日志，约 2 人周，B 阶段一并做。

## 6. 与现有代码的衔接

- `easel/promotion/db.py` 的表结构在服务端换 PostgreSQL，字段不变。
- `easel/promotion/jobs.py` 的线程执行器替换为队列 worker，状态机与幂等键沿用。
- `easel/subscription.py` 的端点常量与服务端网关合一，客户端只感知订阅 Token。
- 本机模式（现仓库）继续可用，作为开源版本与高级模式。
